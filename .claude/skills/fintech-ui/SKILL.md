# 핀테크 모바일 UI 가이드

이 프로젝트는 **카드 결제 문자를 넣으면 자동으로 정리되는 가계부**다. 사용자가 이 화면에서 보는 건 자기 돈이다. 그래서 UI의 목표는 화려함이 아니라 **신뢰감과 빠른 파악**이다. 숫자가 정확해 보이고, 지금 무슨 일이 일어나는지 늘 알 수 있고, 실수해도 되돌릴 수 있다고 느껴야 한다.

판단이 어려울 때 기준은 하나다: **"내 돈을 다루는 앱이라면 이렇게 보여주는 게 안심되나?"**

## 먼저 알아야 할 것

`static/css/style.css` 최상단 `:root`에 이미 디자인 토큰이 정의되어 있다. **새 색상값·반경·그림자를 임의로 쓰지 말고 이 토큰을 쓴다.** 하드코딩된 `#4F46E5` 같은 값이 흩어지면 나중에 색 하나 바꾸는 데 파일을 다 뒤져야 한다.

레이아웃은 **모바일 퍼스트**다. 기본이 모바일이고 `max-width: 768px`로 가운데 정렬된다. 휴대폰에서 먼저 확인하고 넓은 화면을 나중에 본다.

## 색상

토큰은 `style.css`에 있다. 역할만 기억하면 된다.

| 용도 | 토큰 | 쓰는 곳 |
|---|---|---|
| 주색 | `--color-primary` | 주요 버튼, 활성 탭, 강조 숫자 |
| 포인트 | `--color-accent` | 성공 상태, 긍정 지표 |
| 배경 / 표면 | `--color-bg` / `--color-surface` | 페이지 배경 / 카드 |
| 본문 / 보조 | `--color-text` / `--color-text-sub` | 값 / 라벨·설명 |
| 경계 | `--color-border` | 구분선, 입력창 테두리 |
| 에러 | `--color-error` | 에러 메시지, 위험 동작 |

카테고리 7색(`--color-food` ~ `--color-etc`)은 **의미가 고정**되어 있다. 식비는 항상 같은 색이어야 사용자가 차트를 반복해서 읽지 않는다. 장식 목적으로 가져다 쓰지 않는다.

**색만으로 정보를 전달하지 않는다.** 증감을 색으로만 표시하면 색각 이상 사용자는 읽을 수 없다. 색 + 부호(`+`/`−`) 또는 색 + 아이콘을 함께 쓴다.

## 여백과 글자 크기

현재 `style.css`에는 여백·타이포 토큰이 없고 `font-size`가 17종류 흩어져 있다(`0.9rem`, `0.72rem`, `0.68rem` 등). **새로 쓰는 CSS는 아래 계단값만 사용한다.** 기존 코드를 손볼 일이 생기면 가까운 값으로 맞춰 간다.

여백은 4px 배수로:

```
0.25rem(4)  0.5rem(8)  0.75rem(12)  1rem(16)  1.5rem(24)  2rem(32)
```

글자 크기는 6단계로:

```
0.75rem  라벨, 캡션, 탭 이름
0.875rem 보조 설명, 표 본문
1rem     본문 기본
1.25rem  섹션 제목
1.75rem  화면 제목
2rem     핵심 금액 (이번 달 총 지출 등)
```

금액은 크고 굵게, 라벨은 작고 흐리게. 이 대비가 "한눈에 보인다"는 느낌을 만든다. 같은 화면에 큰 숫자가 여러 개면 무엇이 중요한지 알 수 없으니, **화면당 가장 큰 숫자는 하나만** 둔다.

## 터치와 모바일

- 누를 수 있는 것은 **최소 44×44px**. 시각적으로 작아도 `padding`으로 터치 영역을 키운다. 손가락은 마우스보다 훨씬 뭉툭하다.
- 하단 탭 바는 고정이므로 `body`에 `padding-bottom: var(--tab-nav-height)`가 필요하다. 없으면 마지막 항목이 탭에 가린다.
- 가로 스크롤이 생기면 안 된다. 표가 넘치면 컨테이너에 `overflow-x: auto`를 주되, 화면 전체는 넘기지 않는다.
- 입력창 `font-size`는 **16px 이상**. 그보다 작으면 iOS Safari가 포커스 시 화면을 확대한다.

## 상태는 항상 네 가지를 만든다

데이터를 불러오는 화면은 성공만 있는 게 아니다. **네 가지를 다 만들지 않으면 사용자는 빈 화면을 보고 고장 났다고 생각한다.**

1. **로딩** — `showLoading(true)`. 반드시 `finally`에서 `showLoading(false)`로 닫는다.
2. **빈 상태** — "내역이 없습니다" 같은 안내 + 다음에 뭘 하면 되는지. 빈 표를 그냥 두지 않는다.
3. **에러** — `showToast(err.message, 'error')`. **백엔드가 보낸 실제 메시지를 띄운다.** "오류가 발생했습니다"는 사용자가 할 수 있는 게 없다.
4. **성공** — 저장처럼 결과가 눈에 안 보이는 동작에는 토스트로 확인을 준다.

차트도 마찬가지다. 데이터가 없으면 빈 캔버스 대신 안내 문구를 보여준다.

## 한국어 문구

이 앱의 말투는 **친근한 높임말**이다. 짧고, 사용자가 다음에 뭘 할지 알 수 있게 쓴다.

| 상황 | 이렇게 | 이러지 말기 |
|---|---|---|
| 저장 완료 | 저장됐어요 | 저장 성공 / Successfully saved |
| 입력 누락 | 결제 문자를 입력해주세요 | 입력값이 유효하지 않습니다 |
| 파싱 실패 | 문자에서 금액을 읽지 못했어요. 내용을 확인해주세요 | 파싱 에러 (400) |
| 빈 내역 | 아직 내역이 없어요. 문자를 입력해보세요 | 데이터 없음 |

**에러 문구는 원인과 할 일을 같이 준다.** "실패했습니다"로 끝내면 사용자는 같은 걸 반복할 뿐이다. 숫자는 `formatCurrency()`로 천 단위 쉼표와 "원"을 붙인다(`12,000원`). 날짜는 `formatDate()`로 통일한다.

## 지켜야 할 선

사용자를 속이거나 압박하는 패턴은 쓰지 않는다. 돈을 다루는 앱에서 이런 건 신뢰를 한 번에 무너뜨린다.

- 화면에 들어오자마자 전면을 가리는 팝업을 띄우지 않는다. 사용자는 목적이 있어서 들어왔다.
- 뒤로 가기를 막거나 되돌리지 않는다.
- 닫기 버튼을 일부러 작게, 흐리게, 늦게 나타나게 하지 않는다.
- 삭제처럼 되돌릴 수 없는 동작은 **확인을 받고**, 확인 버튼에 무슨 일이 일어나는지 쓴다("삭제" > "확인").
- 파괴적 동작은 `--color-error`로 표시하되, 기본 선택은 안전한 쪽에 둔다.

## 접근성

- 아이콘만 있는 버튼에는 `aria-label`을 준다. 스크린리더는 이모지를 의미 있게 읽지 못한다.
- 탭은 `aria-selected`를 갱신한다(`main.js`의 `initTabs`가 이미 그렇게 한다).
- 본문 대비는 4.5:1 이상. `--color-text-sub`를 작은 글씨에 쓸 때 특히 확인한다.
- 차트에는 `aria-label`로 무엇을 보여주는 차트인지 쓴다.

## 코드 규칙

CSS는 BEM을 느슨하게 쓴다: `블록__요소--수정자` (`.card__title`, `.tab-nav__item--active`). 기존 클래스명을 먼저 찾아보고 있으면 재사용한다.

JS에서 DOM을 만들 때 **사용자 데이터를 `innerHTML`로 넣지 않는다.** 상점명은 사용자가 붙여넣은 문자에서 나온 값이라 스크립트가 섞일 수 있다. `textContent`와 `createElement`를 쓴다(`renderTransactionTable` 참고).

구체적인 컴포넌트 구현(카드, 버튼, 리스트, 배지, 하단 CTA, 탭)은 **`references/components.md`** 에 정리해뒀다. 새 컴포넌트를 만들기 전에 거기 비슷한 게 있는지 먼저 본다.

## 마무리 점검

화면을 만들거나 고친 뒤 확인한다:

- [ ] 색·반경·그림자를 하드코딩하지 않고 토큰을 썼다
- [ ] 여백과 글자 크기가 위 계단값 안에 있다
- [ ] 로딩 / 빈 상태 / 에러 / 성공 네 가지가 다 있다
- [ ] 에러에 백엔드의 실제 메시지가 나온다
- [ ] 누르는 요소가 44px 이상이다
- [ ] 375px 폭에서 가로 스크롤이 없다
- [ ] 사용자 데이터가 `textContent`로 들어간다
- [ ] 아이콘 버튼에 `aria-label`이 있다

## 참고

시각 디자인 방향은 국내 핀테크 앱(토스 등)의 공개된 제품 화면을 **참고**한다. 다만 토스 디자인 시스템(TDS) UI Kit은 라이선스상 **앱인토스 미니앱 개발에만** 사용할 수 있고, 다른 프로젝트에서의 사용·재가공·재배포가 금지되어 있다. 이 프로젝트는 앱인토스 미니앱이 아니고 저장소도 공개되어 있으므로, **TDS의 컴포넌트·토큰·에셋을 가져와 쓰지 않는다.** 이 문서의 값은 전부 이 프로젝트가 자체적으로 정한 것이다.
